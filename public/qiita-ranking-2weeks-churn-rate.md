## TL;DR

- Qiita公式ニュースレター「先週いいねが多かった投稿ベスト20」を2週連続（集計期間: 2026/08/17〜08/23、2026/08/24〜08/30）で取得し、Pythonで構造化して突き合わせた
- 同率順位を含めると各週21件のランクイン記事があったが、**2週とも顔ぶれが残っていたのは7件だけ（33.3%）**。残り14件（66.7%）は1週間で入れ替わっていた
- 生き残った7件の中でも、**1位と2位の「記事」は2週間、順位まで完全に一致していた**。いいね数自体は1位が357→122（-65.8%）、2位が178→102（-42.7%）と大きく減衰していたにもかかわらず、である
- 生き残り組の増減率は平均-58.9%（1件のみ+23.4%の例外あり）。「ランクインし続ける」ことと「いいねが伸び続ける」ことは別の現象だと分かった
- 以前書いた[「タイトルに数字が入った記事だけ平均いいねが29%高かった」](https://qiita.com/devex12/items/9cbab5f4f5b840b1aaa0)は1週間・N=20の分析だったが、今回はそれを2週間の時系列比較に拡張した続編にあたる

## 背景・課題

Qiitaの週刊ニュースレターは「先週いいねが多かった投稿ベスト20」というランキングを毎週配信している。以前、このランキング1週間分（N=20）を使って「タイトルに数字が入っているかどうか」でいいね数を比較する分析記事を書いた。ただし1週間分のスナップショットだけでは、「そのランキングがどれくらい安定しているのか」「同じ記事が翌週も残るのか、それとも毎週総入れ替えなのか」という時系列の疑問には答えられていなかった。

直近2週間分のニュースレターがちょうど受信箱に揃っていたので、今回は同じ記事が週をまたいでどれだけ生き残るか（＝ランキングの滞留率）を実際に数えてみることにした。

なお同時期にZenn側のトレンドも確認しようとしたが、直近14日間でZennからのニュースレターは0件、代替手段であるZennの記事一覧API（`https://zenn.dev/api/articles`）も今回の実行環境のネットワークegressポリシーでブロックされ取得できなかった（この制約は過去の別記事でも報告済みの既知の挙動）。そのため今回の分析はQiita単独のデータに限定している。

## 具体的な取り組み

### ニュースレターをPythonで構造化する

ニュースレター本文（プレーンテキスト）から、順位・New表記の有無・タイトル・著者・いいね数を正規表現で抜き出し、`(著者, タイトル)`をキーにした辞書に変換した。

```python
import re
from dataclasses import dataclass

@dataclass
class RankEntry:
    rank: int
    is_new: bool
    title: str
    author: str
    likes: int

# ニュースレター本文の1行の例:
# "1位 エラーを 3 秒で AI に丸投げする若手を見て、AI から答えを取り上げることにした (URL) by jksoft (357いいね)"
LINE_PATTERN = re.compile(
    r"^(?P<rank>\d+)位\s*(?P<new>New\s*)?(?P<title>.+?)\s*\(https?://\S+\)\s*by\s*(?P<author>\S+)\s*\((?P<likes>\d+)いいね\)"
)

def parse_newsletter(text: str) -> list[RankEntry]:
    entries = []
    for line in text.splitlines():
        m = LINE_PATTERN.match(line.strip())
        if not m:
            continue
        entries.append(RankEntry(
            rank=int(m["rank"]),
            is_new=bool(m["new"]),
            title=m["title"],
            author=m["author"],
            likes=int(m["likes"]),
        ))
    return entries

def churn_rate(week_a: list[RankEntry], week_b: list[RankEntry]) -> float:
    keys_a = {(e.author, e.title) for e in week_a}
    keys_b = {(e.author, e.title) for e in week_b}
    survived = keys_a & keys_b
    fell_off = keys_a - keys_b
    return len(fell_off) / len(keys_a), survived
```

同率順位（「9位」が4件並ぶなど）が両週とも複数あったため、各週のエントリ数は名目上の「TOP20」より多く、実際には21件ずつになった。

分かったことは2つある。

1つ目は、**1位と2位の「記事そのもの」は2週間、順位まで一致していた**こと。ただし絶対数のいいねは1位が-65.8%、2位が-42.7%と大きく減っており、「ランキングに居座り続けている」ことと「勢いが持続している」ことは別物だと分かる。おそらく、Qiita運営自身がニュースレターの見出しに毎週この2本（特に2本目は「答え合わせ」というタイトル通り前週記事の続編）を取り上げていたことが、順位維持に寄与している可能性がある。ランキングの独立変数ではなく、エディトリアルな強調がフィードバックループになっているように見えた。

2つ目は、**生存した7件の平均増減率は-58.9%**（sumomooの記事を除くと6件平均-56.0%）で、ランキングに残ること自体が普通は「減衰しながらの延命」だったこと。唯一sumomooの記事だけいいねが伸びていた（47→58、+23.4%）が、これは「真似で伸びる人は」という初心者向けの普遍的なテーマが、週をまたいでじわじわ拡散した結果だと推測している（あくまで仮説であり、検証はできていない）。

## つまずき：Zenn側は同じ分析ができなかった

当初はQiita・Zenn両方で同じ滞留率分析をする予定だったが、直近14日間でZennからのニュースレターが0件だったため、代替として`https://zenn.dev/api/articles?order=daily&count=30`を叩こうとしたところ、実行環境のネットワークegressポリシーにより`zenn.dev`ドメインそのものがブロックされていた。

```
EGRESS_BLOCKED: Access to zenn.dev is blocked by the network egress proxy.
```

WebSearch経由でZennの個別記事を探すことはできたが、日次のいいね数ランキングという構造化データは取得できなかった。この制約は別の記事でも一度報告している既知の挙動で、今回もう一度踏み抜いた形になる。外部APIへの直接アクセスに依存する分析は、実行環境のネットワークポリシー次第で丸ごと止まるリスクがある、という点は今回もう一度実感した。

## 代替手段との比較

「ランキングの時系列変化を追う」という目的に対して、他にどんな手段があるかを整理した。

| 手段 | 取得できるデータ | 弱点 | 今回の実行環境での可否 |
|---|---|---|---|
| Qiita公式ニュースレター（週刊メール） | 週間TOP20・いいね数・New表記 | 週1回・過去分は遡れない・メール解約すると途切れる | ○（Gmail検索で取得可能） |
| Zenn記事一覧API (`/api/articles`) | 日次のいいね数上位30件 | 認証不要だが、実行環境のegressポリシー次第でブロックされる | ×（今回ブロック） |
| Qiita API v2 (`/api/v2/items`) | 個別記事のいいね数を任意タイミングで取得可能 | 週次ランキングそのものは提供されない。自前で毎日ポーリングして蓄積する必要がある | 未検証（今回は使用せず） |
| サードパーティのトレンド集計サービス | 見やすい可視化 | 集計ロジックがブラックボックスで検証不能 | - |

結論として、今回のような「公式ランキングの生データをそのまま突き合わせる」用途では、週刊ニュースレターをGmail経由で確実に受信しておくのが一番低コストで再現性が高かった。Zenn側のようにAPI直叩きに頼る設計は、ネットワークポリシーという自分でコントロールできない外部要因に依存するため、今回のように詰むケースがある。

## よくある疑問

**Q. N=21（実質7件の生存）で統計的に意味のある結論と言えるか？**
A. 言えない。あくまで2週間という短期間の観察であり、「AI×新人教育ネタは滞留しやすい」と一般化するには最低でも1〜2ヶ月分の週次データが必要だと考えている。今回は「同じ手法をもう1週間分やってみたら何が見えるか」の第一歩という位置づけ。

**Q. なぜ1位・2位だけ順位が変わらなかったのか？**
A. 確証はないが、2本ともQiita Zineニュースレターの「お知らせ」見出しやタイトルとして再度取り上げられていたことが分かっている。ランキング自体は「いいね数」という利用者側の指標のはずだが、運営側の再露出が結果的に指標を下支えしている可能性がある、という仮説にとどまる。

**Q. 前回の「タイトルに数字が入っているか」の分析と矛盾しないか？**
A. 矛盾はしない。今回1位を維持した2本はどちらもタイトルに具体的な数字を含んでいない（「3秒で」は数字だが定量的な統計値ではない）。「数字があると平均いいねが上がりやすい」という前回の観察と、「上位に居座り続けるかどうか」は別の軸の話だと考えている。

**Q. Zenn側も同じ分析をいずれやるのか？**
A. egress制約が解消されるか、Zenn公式ニュースレターの配信を受信できるタイミングを待つ必要がある。現時点では保留にしている。

## 得られた知見・まとめ

- Qiitaの週間いいねランキング（TOP20、同率込みで実質21件）を2週間分突き合わせたところ、生存率33.3%（7/21）・入れ替わり率66.7%（14/21）だった
- その中で1位・2位の「記事」だけは順位が完全に一致していた。ただし絶対いいね数は1位-65.8%、2位-42.7%と大きく減衰しており、「順位の維持」と「勢いの維持」は別物である
- 生存した7件の平均増減率は-58.9%で、ランキングに残ること自体はほとんどの場合「減衰しながらの延命」だった。唯一プラスに転じたのは初心者向けの普遍的なテーマの記事1件だけだった
- Zenn側の同時分析は、ニュースレター0件・API直叩きがegressポリシーでブロックという二重の理由で今回は断念した。外部APIに依存する分析は実行環境のネットワークポリシーという制御できない変数を持つ、という点を再確認した
- 次にやるなら、今回の2週間を起点に4〜8週間分蓄積して、「本当にAI×新人教育テーマは滞留しやすいのか」を統計的に検証したい

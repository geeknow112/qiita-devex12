## 結論から

3つとも用途が違います。比較して1つに絞るより、**使い分けたほうが早いです。**

| 迷っている点 | 選ぶもの | 理由 |
|---|---|---|
| とにかく精度 | Claude Code | 生成コードの正確さで選ぶならここ |
| 費用をかけたくない | Gemini CLI / Kiro | 無料枠、またはプレビュー期間中は無料 |
| IDEから離れたくない | Kiro | IDE統合型。Spec駆動で進む |
| CLIで完結させたい | Claude Code / Gemini CLI | ターミナル前提 |

以下、それぞれの中身を見ていきます。

## 比較対象ツール

| ツール | 提供元 | 料金 | 特徴 |
|--------|--------|------|------|
| Claude Code | Anthropic | 有料（API課金） | 高精度なコード生成 |
| Gemini CLI | Google | 無料枠あり | Google製AIをCLIで利用 |
| Kiro | AWS | 無料（プレビュー中） | IDE統合型、Spec駆動開発 |

## 1. Claude Code

### 概要
AnthropicのClaude APIを活用したコーディングアシスタント。ターミナルベースで動作し、コードの生成・修正・レビューが可能。

### メリット
- コード理解力が高い
- 複雑なリファクタリングも対応
- マルチファイル編集が得意

### デメリット
- API課金が必要（従量制）
- セットアップがやや複雑
- ネットワーク依存

### 料金
- 従量課金制（トークン数に応じて課金）
- 月額の目安：軽い使用で$10〜30程度

## 2. Gemini CLI

### 概要
Google公式のCLIツール。Gemini APIを直接ターミナルから利用でき、コード生成やファイル操作が可能。

### メリット
- 無料枠が充実
- セットアップが簡単
- Googleアカウントがあれば即利用可能

### デメリット
- Claude Codeと比べるとコード精度がやや劣る
- 日本語対応が不完全な場合あり

### 料金
- 無料枠：1日あたり一定量のリクエスト
- 有料プラン：Google AI Studio経由

## 3. Kiro（AWS）

### 概要
AWSが提供するIDE統合型のAIコーディングツール。VSCode拡張として動作し、「Spec駆動開発」という独自のワークフローを採用。

### メリット
- **完全無料**（2026年6月現在、プレビュー中）
- IDE統合で使いやすい
- Spec駆動開発で要件定義から実装まで一貫サポート
- ファイル編集・ターミナル操作も可能
- Steering（カスタムルール）機能

### デメリット
- AWS Builder IDが必要
- プレビュー版のため仕様変更の可能性
- 日本語ドキュメントが少ない

### 料金
- **無料**（プレビュー期間中）

## 実際に使ってみた感想

### Claude Code
セットアップに苦戦しました。特にGemini経由で無料利用しようとしたところ、プロキシサーバーとの互換性問題で断念。結局、正規のAPI契約が必要という結論に。

### Gemini CLI
Google公式だけあってセットアップは簡単。無料で使えるのは大きなメリット。ただし、複雑なコード生成はClaude Codeに軍配が上がる印象。

### Kiro
**個人的に最もおすすめ**。無料でありながら機能が充実しており、IDE統合で直感的に使える。Spec駆動開発は最初戸惑いますが、慣れると要件定義から実装までスムーズに進められます。

## 選び方ガイド

| ユースケース | おすすめツール |
|--------------|----------------|
| 無料で試したい | Kiro or Gemini CLI |
| 高精度なコード生成 | Claude Code |
| IDE統合が欲しい | Kiro |
| CLI派 | Claude Code or Gemini CLI |
| 要件定義から始めたい | Kiro（Spec駆動） |

## まとめ

- **コスト重視**なら → **Kiro**（無料）または **Gemini CLI**（無料枠）
- **精度重視**なら → **Claude Code**（有料）
- **開発体験重視**なら → **Kiro**（IDE統合）

## 選ばないほうがいい場面

比較記事は「どれを選ぶか」で終わりがちですが、外したほうがいい組み合わせもあります。

- **無料だからという理由だけでプレビュー版を業務に入れる。** 仕様変更で手順が通らなくなったとき、期限つきの作業だと詰みます。
- **IDE統合型を、CI上のバッチ処理に使おうとする。** 画面前提の機能は自動実行に向きません。
- **精度が要る場面でツールを複数またぐ。** 出力の癖が混ざると、レビューのほうが重くなります。

料金だけで決めると、切り替えコストのほうが高くつきます。**何に使うかを先に決めて、それに合うものを1つ選んでください。**
